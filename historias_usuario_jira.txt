  ESTRATEGIA DEL PROYECTO

  1. TRABAJO PARALELO POR MÓDULO
     Cada integrante construyó su módulo completo (frontend + backend) en su
     propia rama de Git:
       - Miguel (rama taco): infraestructura compartida + módulo Cliente
       - Gerardo (rama geleon): módulo Administrador
       - Angel (rama angel): módulo Instructor

  2. INFRAESTRUCTURA COMPARTIDA (Miguel)
     Base común que todos utilizan:
       - Prisma ORM + MySQL en Railway (11 tablas, relaciones, enums)
       - Autenticación JWT con bcrypt (login, register, me, profile)
       - Middlewares: auth, authorize, validate, errorHandler
       - Upload de fotos a Cloudinary
       - Documentación: README.md, documentacion_database.md, COMMITS_GUIDE.md

  3. FRONTEND (React 19 + Vite 8 + React Router 7)
     Cada integrante desarrolló las pantallas de su módulo con datos mock
     (mockData.js + localStorage) para validar UX antes de la API real.

  4. BACKEND (Express 5 + Prisma + Zod)
     Cada integrante construyó los endpoints de su módulo contra la misma BD
     en Railway. Todos los endpoints están documentados en COMMITS_GUIDE.md.

  5. PENDIENTE (conexión frontend-backend)
     Última fase: reemplazar mockData.js y localStorage por llamadas HTTP
     autenticadas. Cada integrante conectará su propio frontend con su
     propio backend.

    - 22 rutas frontend navegables y funcionales
    - 26 endpoints backend construidos y probados
    - BD MySQL con 11 tablas + seed data en Railway.app

    - Cloudinary operativo para fotos de perfil
    - 3 ramas Git activas con plan de commits definido
